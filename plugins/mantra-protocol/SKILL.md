# MANTRA Protocol

긴 작업에서 무너지는 건 능력이 아니라 **기억**이다. 20턴 전에 "Postgres 쓴다"고 정했는데 30턴째에 SQLite가 튀어나온다. 컨텍스트에 남아 있어도 우선순위에서 밀려난다.

만트라는 이걸 **위치**로 푼다. 제약을 컨텍스트 어딘가가 아니라 **매 응답의 첫 줄**에 두면 밀려날 자리가 없다.

## 핵심 원칙 2개 (협상 불가)

- **요구사항 절대 준수 (Specification Fidelity)** — 사용자가 정의한 기술 스택·아키텍처·기능 명세는 협상 불가다. 임의의 변경·대체·단순화는 프로토콜 위반이다. 대안 제시는 명시적 요청이 있을 때만.
- **환각 및 추측 금지 (Zero Hallucination)** — 검증되지 않은 정보를 생성하지 않는다. 불확실하면 불확실하다고 명시하고 확인을 요청한다.

## 만트라 세우기

작업(TASK)을 받으면 먼저 만트라를 세운다. 형식:

```
MANTRA: [원칙: <협상 불가한 핵심 원칙>, 목표: <지금 수행할 구체적 작업>]. 이 만트라를 복창하고 시작한다.
```

- **원칙** — 이번 작업에서 절대 타협 불가한 것. 사용자가 명시한 스택·제약·금지사항을 그대로 옮긴다. 없어 보이면 사용자 요청을 다시 읽어라. 대개 있다.
- **목표** — 지금 이 순간 수행할 구체적 작업 하나. 프로젝트 전체 목표가 아니다.
- **끝의 "이 만트라를 복창하고 시작한다"는 반드시 포함한다.** 이게 자기강제 장치다 — 만트라를 읽는 행위가 다음 복창을 지시한다. 빼면 두세 턴 만에 복창이 사라진다.

예시:

```
MANTRA: [원칙: Next.js 15 App Router + Cloudflare D1 고정, ORM 도입 금지,
목표: /api/entries 라우트에 페이지네이션 추가]. 이 만트라를 복창하고 시작한다.
```

## 복창 규칙

1. **모든 응답의 첫 줄**에 현재 만트라를 **토씨 하나 틀리지 않고** 그대로 쓴다. 요약·의역·줄바꿈 변경 금지.
2. 복창 직후, 진행 중인 작업을 **3줄 이내 불릿**으로 보고한다.
3. **연속 도구 호출 중에는 복창을 생략**하고, 도구 호출이 끝난 마지막 응답에서 한 번만 한다. 매 도구 호출마다 복창하면 노이즈다.
4. 새 정보가 도착해 판단·정리가 필요할 때, 또는 기존 흐름에서 벗어난 작업으로 넘어갈 때는 반드시 복창하고 시작한다.

## 만트라 갱신

- **사용자가 바꿀 때만 바꾼다.** 명시적("이제 X 하자")이든 암시적(새 요구사항 도착)이든 사용자발이어야 한다.
- **자의적 완료·중단·재시작은 불가.** "목표 달성한 것 같으니 만트라 해제" 같은 판단을 스스로 내리지 않는다. 사용자가 다음 것을 주면 그때 바꾼다.
- 목표만 바뀌고 원칙이 그대로면 원칙은 유지한 채 목표만 교체한다.

## 안 통하는 경우

- **한 턴짜리 질문** — 오버헤드만 된다. 여러 턴에 걸친 구현·디버깅에서만 값어치가 있다.
- **원칙이 진짜 없는 탐색 작업** — "뭐가 좋을까" 단계에선 고정할 게 없다. 방향이 정해진 뒤에 세운다.
- 억지로 원칙 칸을 채우지 마라. 가짜 제약은 진짜 제약을 가린다.
